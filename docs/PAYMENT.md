# การชำระเงินและการเงิน (spec §4.7)

สถานะ: **P2a + P2b เสร็จ** — ค่าลงทะเบียน → ใบแจ้งชำระ + PromptPay → แนบสลิป/รับเงินสดหน้างาน → ตรวจสอบ → หมดเวลา → ชุดนำส่งกองคลัง → เลขที่ใบเสร็จ → คืนเงิน · ส่วนที่รอข้อมูลกองคลังดูท้ายเอกสาร

## หลักการ
1. **ใบเสร็จทางราชการออกโดยกองคลังเท่านั้น** — ระบบแสดงเพียง "หลักฐานการชำระเงิน (ไม่ใช่ใบเสร็จรับเงิน)" และบันทึกเลขที่ใบเสร็จที่กองคลังออก
2. **ยอดเงินคำนวณที่ backend** จากอัตรา ณ เวลาออกใบแจ้งชำระ แล้ว snapshot ลง `payment_orders.fee_snapshot` (บัญชีรับเงิน/รหัสรายได้ก็ snapshot) — แก้อัตราหรือบัญชีภายหลังไม่กระทบใบที่ออกไปแล้ว
3. **เงินเป็นทศนิยมแบบ Decimal(12,2)** ใน DB และ string บน wire ไม่ใช้ floating point
4. **Append-only**: ledger แก้/ลบไม่ได้, `amount` ทุกตารางการเงินแก้ไม่ได้, ยอดรวมชุดนำส่งแก้ไม่ได้ (trigger ใน DB) — การแก้ไขทำด้วยรายการใหม่ (WAIVER / REVERSAL / REFUND)
5. **แยกสถานะ**: การลงทะเบียน / ใบแจ้งชำระ / รายการชำระ / ชุดนำส่ง / ใบเสร็จ
6. **แบ่งแยกหน้าที่ (SoD)**: ผู้ตรวจสลิป ≠ ผู้ชำระ/ผู้ส่งสลิป · ผู้ยกเว้นค่าธรรมเนียม ≠ ผู้ลงทะเบียน · ผู้รับชุดนำส่ง (กองคลัง) ≠ ผู้จัดทำ/ผู้ส่ง

## การเลือกอัตรา (`apps/api/src/payments/fee.ts`, มี unit test)
1. ใช้เฉพาะอัตราที่เปิดใช้และอยู่ในช่วง `valid_from ≤ เวลา < valid_until`
2. อัตราที่ระบุประเภทผู้เข้าร่วมชนะอัตราทั่วไป
3. ถ้ามีหลายอัตราที่ใช้ได้ ใช้อัตราต่ำสุด (Early bird ทับช่วงอัตราทั่วไปได้โดยไม่เก็บเกิน)
4. อัตรา 0 บาท = ยืนยันทันทีไม่ออกใบแจ้งชำระ · ไม่มีอัตราที่ใช้ได้ = `FEE_NOT_AVAILABLE`

กิจกรรมเป็น "มีค่าใช้จ่าย" เมื่อมีอัตรา > 0 อย่างน้อย 1 อัตรา และต้องระบุบัญชีรับเงิน (FIN-4) จึงจะบันทึกได้ — workflow อนุมัติจะเพิ่มขั้น "กองคลังตรวจสอบอัตรา บัญชีรับเงิน และรหัสรายได้" อัตโนมัติ หลังอนุมัติแล้วแก้อัตราไม่ได้

## วงจรการชำระ
```text
ลงทะเบียน ─(มีที่นั่ง, ต้องชำระ)→ PENDING_PAYMENT + ใบแจ้งชำระ UNPAID (กันที่นั่ง, ครบกำหนด = min(ตอนนี้ + payment_window_hours, เวลาเริ่มงาน), อย่างน้อย 1 ชม.)
  แนบสลิป (ก่อนครบกำหนด) → รายการ SUBMITTED, ใบแจ้ง PENDING_VERIFICATION  ← ไม่ถูกตัดสิทธิ์ระหว่างรอตรวจ
    ตรวจผ่าน  → รายการ VERIFIED, ledger PAYMENT (−), ใบแจ้ง PAID, ลงทะเบียน CONFIRMED
    ไม่ผ่าน   → รายการ REJECTED, ใบแจ้ง UNPAID, ขยายกำหนดอย่างน้อย 24 ชม. (ไม่เกินเวลาเริ่มงาน)
  ยกเว้นค่าธรรมเนียม (payment:waive + เหตุผล) → ledger WAIVER, ใบแจ้ง WAIVED, CONFIRMED
  ครบกำหนดยังไม่ชำระ → ใบแจ้ง EXPIRED, ลงทะเบียน EXPIRED, คืนที่นั่ง, เลื่อนรายชื่อสำรองคนถัดไป (ได้ใบแจ้งชำระใหม่)
ยกเลิกการลงทะเบียน → สลิปรอตรวจ VOIDED, ใบแจ้งที่ยังไม่ชำระ CANCELLED, ใบที่ชำระแล้ว REFUND_PENDING
ยกเลิกกิจกรรม       → เช่นเดียวกันทั้งกิจกรรม
```
**หมดเวลา**: BullMQ delayed job ต่อใบแจ้ง (ตรงเวลา) + sweeper ทุก 1 นาที (กันงานหาย) เรียกฟังก์ชันเดียวกันซึ่ง idempotent และล็อกแถว — รันหลาย replica ได้ (`QUEUE_ENABLED=false` ปิด worker ในการทดสอบ)

## สลิป
- อัปโหลดแบบ multipart ตรวจชนิดจาก magic number (JPG/PNG/PDF เท่านั้น) จำกัดขนาด `SLIP_MAX_BYTES` (ค่าเริ่มต้น 5 MB)
- เก็บใน private bucket ด้วย key ที่เดาไม่ได้ เจ้าหน้าที่ดูผ่าน `GET /finance/payments/:id/slip` (ตรวจสิทธิ์ + data scope; storage ไม่เปิดสู่ภายนอก)
- SHA-256 ซ้ำกับรายการที่ยังมีผล → `DUPLICATE_SLIP` (ตรวจก่อนอัปโหลด + partial unique index)
- ผู้ไม่เข้าสู่ระบบใช้เลขอ้างอิง + token (token เก็บเป็น hash)

## PromptPay
`promptPayPayload(promptPayId, amount)` (EMVCo + CRC16 ทดสอบเทียบไลบรารีอ้างอิง) สร้างจาก snapshot บัญชีรับเงิน แสดงเป็น QR เฉพาะใบแจ้งสถานะ UNPAID — **รหัสพร้อมเพย์ใน seed เป็นค่าตัวอย่าง** ต้องแทนที่ด้วยของจริงจากกองคลัง

## ชุดนำส่งกองคลัง
```text
DRAFT ─submit→ SUBMITTED ─receive→ RECEIVED ─(บันทึกเลขที่ใบเสร็จครบ)→ RECEIPTS_ISSUED
                         └return→ RETURNED (ปล่อยรายการคืน จัดทำชุดใหม่ได้)
```
- 1 ชุด = 1 กิจกรรม รวมรายการที่ VERIFIED และยังไม่อยู่ในชุดอื่น (ล็อกแถวกิจกรรมระหว่างสร้าง)
- ยอดรวม/รายการถูกตรึงตอนสร้าง; ตอนส่งเก็บ snapshot JSON ของรายงานที่ส่งจริง
- รายงานนำส่ง Excel (TH Sarabun New, พ.ศ., ยอดเป็นตัวอักษร, ช่องลงนาม) — แบบฟอร์มจริงรอ FIN-1
- เลขที่ใบเสร็จ: unique (ปีงบประมาณ, เล่มที่, เลขที่) — หน้าจอบันทึกเป็นช่วงเลขต่อเนื่องได้

## สิทธิ์ (ค่าเริ่มต้น ปรับได้ที่บทบาท)
| บทบาท | ทำได้ |
|---|---|
| ORG_FINANCE_OFFICER (การเงินหน่วยงาน) | ดู/ตรวจสลิป (`payment:verify`), ยืนยันยอดกะ/ยกเลิกรายการเงินสด, ยื่นคำขอคืนเงิน, สร้างและส่งชุดนำส่ง |
| FINANCE_OFFICER (กองคลัง) | ขั้นตรวจสอบการเงินในการอนุมัติ, รับ/ส่งกลับชุดนำส่ง, บันทึก/ยกเลิกเลขที่ใบเสร็จ, อนุมัติ/จ่ายคืนเงิน, บัญชีรับเงิน/รหัสรายได้ |
| EVENT_CASHIER | เปิด/ปิดกะ รับเงินสดหน้างาน บันทึกการนำส่ง |
| EVENT_MANAGER | ตั้งค่าอัตรา (ก่อนอนุมัติ), ดูรายการชำระ |

ผู้ตรวจสลิปจริง (หน่วยงาน หรือ กองคลัง) รอยืนยัน FIN-6

## รับชำระหน้างาน (กะรับเงิน)
```text
OPEN ─close(นับเงิน)→ CLOSED ─remit(เลขที่ใบนำส่งเงิน)→ REMITTED ─confirm→ CONFIRMED
```
- ผู้รับเงิน (EVENT_CASHIER) เปิดกะต่อกิจกรรม (1 กะที่เปิดอยู่ต่อคนต่อกิจกรรม) ระบุเงินทอนตั้งต้นได้
- รับเงินตามใบแจ้งชำระที่ยัง UNPAID เท่านั้น ยอดมาจาก snapshot (ผู้รับเงินพิมพ์ยอดเองไม่ได้) ต้องส่ง Idempotency-Key กันกดซ้ำ
  → รายการ ONSITE (VERIFIED), ledger PAYMENT, ลงทะเบียน CONFIRMED, พิมพ์ "หลักฐานการชำระเงิน (ไม่ใช่ใบเสร็จ)"
- รายการที่มีสลิปรอตรวจรับเงินสดซ้ำไม่ได้; รับชำระของตนเองไม่ได้
- ยกเลิกรายการ (`cashier:void`) ได้เฉพาะตอนกะยังเปิด โดยคนที่ไม่ใช่ผู้รับเงิน → ledger REVERSAL, ใบแจ้งกลับเป็น UNPAID (ขยายเวลาอย่างน้อย 24 ชม.)
- ปิดกะ: ระบบตรึงยอดในระบบ + ยอดนับได้ (trigger ห้ามแก้) ส่วนต่าง ≠ 0 ต้องมีหมายเหตุ
- เงินสดเข้าชุดนำส่งกองคลังได้ **หลังการเงินหน่วยงานยืนยันยอดกะแล้วเท่านั้น** (ผู้ยืนยัน ≠ ผู้รับเงิน)

## คืนเงิน
```text
REQUESTED ─approve→ APPROVED ─pay(เลขอ้างอิงการโอน)→ PAID (ledger REFUND)
          └reject→ REJECTED
```
- ยื่นโดย `refund:create` (การเงินหน่วยงาน/กองคลัง) จากรายการที่ชำระแล้ว คืนบางส่วนได้ ไม่เกินยอดที่รับจริง − คำขอที่ยังมีผล
- อนุมัติ `refund:approve` และจ่ายคืน `refund:refund` (กองคลัง) — ทั้งสองต้องไม่ใช่ผู้ยื่น
- เลขบัญชีผู้รับเงินคืนเข้ารหัส AES-256-GCM แสดงแบบ ••••1234; ดูเลขเต็มได้เฉพาะผู้จ่ายคืน และบันทึก audit ทุกครั้ง
- สถานะใบแจ้งชำระคำนวณจาก ledger: คืนครบ → REFUNDED, คืนบางส่วน → PARTIALLY_REFUNDED, มีคำขอค้าง/ยกเลิกการลงทะเบียนแล้วยังไม่คืน → REFUND_PENDING
- การคืนเงินไม่ยกเลิกการลงทะเบียนให้อัตโนมัติ (หน้าจอเตือนถ้ายังยืนยันอยู่)

## ยกเลิกเลขที่ใบเสร็จ
`receipt:void` + เหตุผล → เลขเดิมคงอยู่สถานะ VOIDED (ไม่ลบ), ชุดนำส่ง RECEIPTS_ISSUED กลับเป็น RECEIVED เพื่อบันทึกเลขใหม่

## รอข้อมูลจากกองคลัง (P2c)
รายงานนำส่ง/ใบนำส่งเงิน PDF ตามแบบฟอร์มจริง (FIN-1), กระทบยอดกับ statement ธนาคาร, แก้อัตราหลังอนุมัติ → ส่งอนุมัติใหม่ (`FEE_CHANGE`), ข้อมูลออกใบเสร็จในนามนิติบุคคล (FIN-9), ระเบียบยกเลิกใบเสร็จ/คืนเงิน (FIN-8), บันทึกสำรองเมื่อเครือข่ายขัดข้องที่จุดรับเงิน (FIN-12), adapter ตรวจสลิปอัตโนมัติ / payment gateway (ปิดเป็นค่าเริ่มต้น)
